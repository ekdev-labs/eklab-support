# Security reporting

Do not disclose suspected vulnerabilities in public issues, comments or attachments.

Use [GitHub private vulnerability reporting](https://github.com/ekdev-labs/eklab-support/security/advisories/new).
The report is shared privately with the maintainers through GitHub's advisory workflow.
It does not grant access to the library's private source repository.

Include, where available:

- Affected package names and exact versions.
- A description of the vulnerability and its potential impact.
- Minimal reproduction steps using synthetic data.
- Framework, browser and operating system versions.
- Any mitigation you have identified.

Never send passwords, access tokens, personal information or real customer data.
Reports are assessed individually; this policy does not promise a response deadline, bounty or particular fix date.
Supported product releases will be listed when releases are available. Unreleased foundation work is not a production support commitment.
